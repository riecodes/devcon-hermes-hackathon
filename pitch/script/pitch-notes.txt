WHAT IS TYPESAFE AI? (brief, if asked)
====================================================================
TypeSafe AI makes "System One" models: fast models built to make decisions, not to write text.
Their first model is Jev (we used jev-1.13.0).

How it works: you send a "state" (here, a customer's complaint) plus typed questions.
Jev answers every question at once, in parallel, with a probability for each answer:
  - yes/no questions ("Is this about a late delivery?" -> 0.95)
  - scores ("How likely is this customer to leave? Low / Medium / High")
  - choices (pick one label from a list)
Software can use the answers directly. Nothing to parse, no invented labels.

Why it matters: it's fast and cheap. TypeSafe publishes 70 to 500 ms per decision and
$0.042 per million input tokens, with output free. Early access opened Sept 15, 2026.

Say it in one line:
"Jev is like an if-statement with judgment: it reads the complaint and answers our questions
 in half a second, for a fraction of a cent."

HOW THE THREE LAYERS CONNECT (what we built)
====================================================================
LAYER 3, THE FACE: Desktop plugin  (desktop-plugin/suki-pulse/plugin.js)
  - A "Suki Pulse" pane inside Hermes Desktop: branch picker + 4 buttons
    (Pulse check, Fix top root cause, Recover riskiest customer, Branch scorecard).
  - 4 Ctrl+K commands and a Ctrl+Shift+P shortcut.
  - Clicking a button types a prompt into the chat for you, for example:
    "Use the suki-pulse skill: run a pulse check for branch TMR."
  - It also draws 2 native result cards: "Root causes" and "Impact" (before and after).

LAYER 2, THE PLAYBOOK: Skill  (skills/suki-pulse/SKILL.md)
  - The prompt names the skill, so Hermes loads it. The skill tells Hermes which tools to call,
    in what order, and how to answer. 3 workflows:
    A. Pulse check: scorecard -> Jev triage -> root-cause rollup -> headline, card, table, cost.
    B. Fix: plan up to 6 actions on BOTH sides, ASK for a yes, run them, re-run the scorecard.
    C. Recover a customer: their full story, then resolve, reply and give goodwill points.
  - Rules: never write before the user confirms, never lower a customer's points,
    only quote real numbers from the tools.

LAYER 1, THE HANDS: MCP server  (mcp-server/server.py, registered in Hermes as "suki")
  - 10 tools, each answering one business question. No generic "run any SQL" tool.
    Read:  list_branches, pulse_scorecard, triage_feedback, root_cause_rollup, get_customer_story
    Act:   resolve_ticket, reply_to_review, fix_loyalty_balance, draft_purchase_orders,
           flag_rider_for_coaching
  - triage_feedback is where Jev comes in: one Jev call per complaint, 8 questions
    (6 root causes, churn risk, urgency). Results are cached so re-runs are free,
    with a keyword fallback if Jev is busy.
  - root_cause_rollup joins each cause to operations: late delivery -> riders and deliveries;
    spoiled -> expiring stock and late suppliers; out of stock -> items with no purchase order;
    loyalty -> ledger mismatches.
  - Every write is logged to a pulse_actions table.

THE LOOP, END TO END (one click):
  Click "Pulse check" in the pane
   -> the plugin sends the prompt to the chat
   -> Hermes loads the suki-pulse skill
   -> the skill calls the suki MCP tools (Jev labels the complaints, SQL finds the causes)
   -> Hermes replies with a card line holding the real numbers
   -> the plugin draws that line as a native "Root causes" card in the chat.
  GUI action -> skill -> MCP -> real data back in the GUI.

Say it in one line:
"The pane is the button, the skill is the brain's checklist, the MCP server is the hands,
 and the answer comes back as a card in the same window."
